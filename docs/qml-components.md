# QML components available on the device

Generated by probing the device itself, not read from documentation:
`N9_PROBE_QML=<file> WebMee` tries to create each candidate type and reports
whether it resolves. 470 candidates were tried; **271 exist**.

**Why this file exists.** QML types resolve at *creation* time, not load time.
A type that does not exist on this device produces no error at startup and no
error in the log — the page simply fails to open when the user taps it. That
cost real debugging time with `SelectionListItem`, which is a Qt Components type
but **not a Harmattan one**.

Check here before using any component you have not already used in this project.

## How to verify a type yourself

```sh
printf 'com.nokia.meego 1.1 SomeType\n' > /home/user/c.txt
N9_PROBE_QML=/home/user/c.txt invoker --single-instance --type=d .../WebMee
# -> "com.nokia.meego 1.1 SomeType ok"  or  "... MISSING"
```

`N9_TEST_QML=1` instantiates every page of this app and reports errors, which
catches the same class of bug for code already written.

## Traps

- **`SelectionListItem` does not exist here.** `SelectionDialog` does. Pair it
  with a plain `Button` that calls `open()`.
- **`qmldir` is not the whole story** — see the plugin-registered list above.
- **Many CamelCase names in the plugin binary are enum values, not types**
  (`DialogStatus`, `PageOrientation`, `Clockwise`, `BodyTextFont`, ...). 199 of
  470 candidates probed MISSING for exactly this reason. Do not infer a type
  from `strings` output.
- **`com.nokia.extras` needs version 1.1**; `InfoBanner` is not found at 1.0.
- **`Style` components are real types** (`ButtonStyle`, `BusyIndicatorStyle`,
  ...) and are how you set `platformStyle`.
